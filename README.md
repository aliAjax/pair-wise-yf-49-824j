# pair-wise-yf-49 法庭证据展示与庭审顺序控制

源提示词摘要：法官、书记员和双方代理人共同维护庭审证据目录，控制当前展示、证据顺序、敏感信息遮罩、计时、异议分支和庭审阶段；操作屏与公开屏分离，离线时仍可展示并能恢复本地快照。

## 技术栈

React19、TypeScript、Vite、Arco Design、Redux Toolkit、React Router、React Hook Form、Zod、i18next。

## 本地运行

```bash
npm install
npm run dev
npm run build
```

开发端口：62014

## 操作屏 / 公开屏分离与离线合并

操作台与公开屏常不在同一网络，系统按「字段级版本 + 本地发件箱」处理两边差异：

- **断网修改不盖回在线版本**：编号、标题、备注、遮罩、顺序的改动只进入本地 outbox（`src/store/localStore.ts` 独立持久化，刷新/断电不丢），不做整表覆盖。
- **字段级版本合并**：在线版本（`src/store/server.ts`，字段各自带 `rev/updatedAt/origin`）按 `baseRev` 校验提交；同一项已被对端改动时服务端拒绝覆盖并回报冲突（`src/store/merge.ts`）。
- **失败重试**：同步失败后整批保留，按 1s、2s、4s…（上限 30s）指数退避重试，直到写入成功（`src/store/sync.ts`）。
- **两边改动 → 重新确认并保留两个版本**：同一证据同一字段两边都改过，两个版本都保留、按时间给出暂定建议，并进入「冲突核对」页人工重新确认；确认前**公开屏一律拦截**，编号、标题与遮罩均不公示。采用本地版本时以对端修订号为新 base 重新提交，采用对端版本则本地对齐。
- **旧数据不补号不覆盖**：迁移前缺版本信息的字段 `rev=null`，标为「旧数据·待确认」；人工核对只置确认标记，不补修订号、不覆盖在线版本。
- **公开屏一致**：公开屏预览的编号、标题、遮罩全部读取合并结果；证据处于冲突或含未确认旧字段时给出明确暂缓/提示状态。

页面内提供「模拟断网」「模拟对端修改第一项标题」「模拟下次同步失败」三个开关/按钮，可直接走查上述流程。
